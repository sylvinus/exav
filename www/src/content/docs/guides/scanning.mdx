exav prints `clamscan`'s output format. The flags are exav's own, and there is a
fourth exit code. This guide covers everyday scanning; see the
[CLI reference](/reference/cli/) for every flag.

## Targets

```sh
exav file.bin                     # scan one file
exav /var/www                     # scan a directory, recursively
exav --no-recursive /var/www      # just the directory's own files
exav --quiet /data                # only print errors and detections
cat file.zip | exav -             # scan stdin
exav https://host/obj.zip         # scan over HTTP range requests (needs an `http-scan` build + EXAV_ALLOW_HTTP_SCAN=1)
exav -d ./mydb /data              # use a signature database (file or dir)
```

All examples assume signatures are loaded, with `-d` / `--sig-dir` or from the
default `--sig-dir` directory. See [Signatures](/guides/signatures/).

### Stdin

Stdin, and a FIFO given as a path, is buffered before it is scanned: in memory
up to `--spill-threshold-bytes` (16 MiB), then in a temporary file up to
`--max-spill-bytes` (2 GiB). The buffered stream then gets the same scan as a
file, with the same options. A stream past `--max-input-bytes` or the spill
ceiling is treated as a file past `--max-input-bytes`: what was held gets the
whole scan, and without a detection in it the stream is `LIMITS-EXCEEDED`. See
[Streaming & memory](/concepts/streaming-memory/).

### Scanning over HTTP costs bandwidth, not memory

A seekable source may be read more than once. Some checks need a whole object at
a time (overlapping ZIP records, overlapping partitions, broken media and
executable headers) while extraction walks members one at a time, so the object
is read again to run them. Over `http(s)://` a range source is fetched a small,
constant number of times, and an object under `--max-object-bytes` is likely
fetched in full.

To pay in disk instead of transfer (metered egress, a slow link, per-request
billing), download the object and scan the file:

```console
curl -sO https://host/obj.zip && exav obj.zip
```

Over `--max-object-bytes`, an archive in a streamable format (ZIP, tar, 7z, CAB
and most others) is still walked member by member, but the checks on its own
bytes are skipped; one that cannot be streamed (RAR, for instance) is not opened.
Either way it is reported `LIMITS-EXCEEDED`.

## Output format

The human-readable output is one line per file, followed by a `clamscan`-style
summary:

```console
/path/to/file: Win.Trojan.Agent-1234 FOUND
/path/to/clean: OK
/path/to/missing: No such file or directory ERROR
/path/to/huge.bin: file size 9663676416 exceeds max-input-bytes 4294967296; scanned first 4294967296 bytes only LIMITS-EXCEEDED PARTIAL
/path/to/secret.zip: encrypted archive member PASSWORD-PROTECTED PARTIAL
```

A file that could not be fully examined ends with the reason, then the
[category](/reference/verdicts/) of the condition, then the status `PARTIAL`.

`--quiet` suppresses the `OK` lines and the summary; `-v` adds detail.

### JSON output

`--json` emits newline-delimited JSON: one object per scanned input, then a
summary object:

```console
$ exav --json /data
{"file":"/data/file","status":"FOUND","signature":"Win.Trojan.Agent-1234","method":"pattern","offset":1234}
{"file":"/data/clean","status":"OK"}
{"file":"/data/huge.bin","status":"PARTIAL","category":"LIMITS-EXCEEDED","reason":"file size 9663676416 exceeds max-input-bytes 4294967296; scanned first 4294967296 bytes only"}
{"summary":{"scanned":3,"infected":1,"partial":1,"errors":0,"data_scanned_bytes":4294972634,"elapsed_secs":0.042}}
```

`status` is on every result object and is the word the human line ends with.
`category` only appears on a `PARTIAL`, so filter on `status`:

```sh
exav --json /data | jq 'select(.status=="PARTIAL")'             # not fully examined
exav --json /data | jq 'select(.status|test("FOUND|PARTIAL"))'  # everything unclean
```

### Verbose findings

`-v` / `--verbose` prints informational findings (detected file type, entropy,
imphash, ML score) alongside the verdict.

## All-match mode

By default exav stops at the first matching signature per file. `--all-matches`
reports every match (`clamscan`'s `--allmatch`):

```sh
exav --all-matches /data
```

## Filters

Include and exclude by path regex, repeatable, with `clamscan`'s semantics:

```sh
exav /data --exclude '\.log$' --exclude-dir 'node_modules' --include '\.exe$'
```

`--exclude-dir` matches a directory's own path, which has no trailing separator:
`node_modules` skips the directory, while `/node_modules/` only skips what is
nested below it and lets files directly inside through. To anchor it, write
`/node_modules($|/)`.

## Exit codes

| Code | Status | Meaning |
|---|---|---|
| `0` | `OK` | Everything fully scanned, no matches. |
| `1` | `FOUND` | At least one detection. |
| `2` | `ERROR` | exav could not do its job: an unreadable path, a database that would not load. |
| `3` | `PARTIAL` | A file could not be fully examined: `LIMITS-EXCEEDED`, `UNSCANNABLE` or `PASSWORD-PROTECTED`. |

`3` is kept apart from `2` so that "the scanner broke" and "this file needs a
decision" are different signals. [`--partial-as`](/reference/cli/#what-an-unscannable-object-becomes)
maps `3` to another status. See [Verdicts & exit codes](/reference/verdicts/).

## Encrypted archives

An encrypted member is reported `PASSWORD-PROTECTED`. Supply passwords to decrypt
it and scan inside:

```sh
exav --passwords secret --passwords hunter2 /data     # tried in order
```

Passwords also load from a ClamAV `.pwdb` database in the signature directory.
exav decrypts ZIP (ZipCrypto and WinZip AES), encrypted DMG, 7z AES-256, PDF, and
Office: legacy XLS (RC4, RC4 CryptoAPI, XOR) and OOXML (AES standard and agile).
For Office it also tries Excel's default `VelvetSweatshop` and the empty password
without being asked. RAR AES and PKWARE Strong Encryption are detected but not
decrypted.

An encrypted archive appended to a picture or a document (a polyglot that archive
tools open by its trailing directory) is reported the same way once its structure
is confirmed.

## Heuristics

A small set of low-false-positive heuristics runs by default, the ones ClamAV
itself reports (imphash matching and the PDF obfuscated-name check).
`--detect exav-heuristics` adds exav's own (PE entropy, packer detection, TLSH
fuzzy matching, a static ML baseline scorer), which carry more false-positive
risk and are opt-in:

```sh
exav --detect exav-heuristics -v sample.exe
```

`--detect` takes `all`, `none`, or a comma-separated list of `exav-heuristics`,
`macros`, `broken`, `broken-media`, `partition-intersection`, `phishing`,
`packed`, `pua`.
