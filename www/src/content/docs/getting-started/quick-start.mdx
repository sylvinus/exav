This walks you from a freshly built binary to a working scan. You need
[exav installed](/getting-started/installation/) first.

<Aside type="caution" title="exav ships no signatures">
exav does not bundle the GPL-licensed ClamAV signature database, and with no real
signatures loaded it refuses to run. Fetching signatures is the first step below.
</Aside>

<Steps>

1. **Get ClamAV signatures** with Cisco's own updater:

   ```sh
   pipx install cvdupdate      # or `pip install --user cvdupdate`
   cvd update
   ```

   This populates `~/.cvdupdate/database` with `main.cvd`, `daily.cvd` and
   `bytecode.cvd`. If `freshclam` already keeps a database current, use its
   directory instead (usually `/var/lib/clamav`) in the commands below. See
   [Signatures](/guides/signatures/) for the licensing background and
   third-party feeds.

2. **Check that detection works** with the EICAR test file, which every scanner
   detects and which is harmless:

   ```sh
   printf '%s%s' 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-' \
     'TEST-FILE!$H+H*' > eicar.com
   exav -d ~/.cvdupdate/database eicar.com
   ```

   ```console
   eicar.com: Eicar-Test-Signature FOUND
   ```

3. **Scan a file.** The output follows `clamscan`'s format:

   ```sh
   exav -d ~/.cvdupdate/database suspicious.bin
   ```

   ```console
   suspicious.bin: OK
   ```

4. **Scan a directory.** It is recursive by default; `--quiet` prints only
   detections, partial results and errors:

   ```sh
   exav -d ~/.cvdupdate/database --quiet /var/www
   ```

5. **Scan stdin** with `-`:

   ```sh
   cat backup.tar.gz | exav -d ~/.cvdupdate/database -
   ```

</Steps>

## Exit codes

The status is the last word on each result line, and each status has an exit
code: `0` for `OK`, `1` for `FOUND`, `2` for `ERROR` (exav could not do its job),
and `3` for `PARTIAL` (something could not be fully examined).

<Aside type="note">
`clamscan` reports `OK` and exits `0` for a file it could not fully scan; exav
exits `3`, so a CI job should not treat `3` as a pass. See
[Verdicts & exit codes](/reference/verdicts/), and
[`--partial-as`](/reference/cli/#what-an-unscannable-object-becomes) to map `3` to
another status.
</Aside>

## Faster startup: build a database once

Loading Cisco's raw database (`main.cvd` + `daily.cvd`) builds a large in-memory
automaton, which takes time and several GB of transient RAM. Do it once and reuse
the result:

```sh
exav -d ~/.cvdupdate/database --build-db exav.exavdb   # heavy, run daily in CI
exav -d exav.exavdb /data                              # fast cold start
```

A `.exavdb` is tied to the exav version that built it: after upgrading exav,
rebuild it. See the [prebuilt database guide](/guides/prebuilt-database/).

## Run it as a daemon

Load the database once and serve scans over a socket, so callers pay no per-scan
load cost. The daemon stays in the foreground, so run the client from a second
terminal:

```sh
exav --listen "$XDG_RUNTIME_DIR/exav.sock" -d exav.exavdb   # load once, serve
exav --connect "$XDG_RUNTIME_DIR/exav.sock" /data           # client
```

A daemon can also keep its signatures current itself, fetching from a mirror
with `--auto-update` (a `--features http` build); see
[Signatures](/guides/signatures/#built-in-updater---auto-update).

`--listen` accepts connections and `--connect` makes one. The protocol travels in
the address: `--listen icap://0.0.0.0:1344` serves ICAP, and naming both serves
both from one process. ClamAV's own `clamdscan` works too, given a `clamd.conf`
whose `LocalSocket` or `TCPSocket` points at the daemon.

See the [daemon guide](/guides/daemon/).
