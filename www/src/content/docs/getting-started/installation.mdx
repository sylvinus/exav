exav runs on Linux, macOS and Windows and ships as a single binary. The Linux
release builds are static (musl); the macOS and Windows builds link the system
libraries.

## From crates.io

```sh
cargo install exav
```

That installs the `exav` binary with the default pure-Rust build, which handles
every supported archive format. The library crates it is built from (`exav-*`)
are not needed to install it.

For a build with [HTTP support](/reference/feature-flags/#adding-http-support)
(URL scanning and signature updates over HTTP(S)):

```sh
cargo install exav --features http
```

See [Feature flags](/reference/feature-flags/) for all build options.

<Aside type="caution" title="Rust 1.91 or newer">
If the build fails on syntax, check `rustc --version` first. The workspace
`rust-version` in `Cargo.toml` is authoritative.
</Aside>

## Build from source

<Steps>

1. Install a Rust toolchain (1.91 or newer) via [rustup](https://rustup.rs/).

2. Clone and build:

   ```sh
   git clone https://github.com/sylvinus/exav
   cd exav
   cargo build --release -p exav      # -> target/release/exav
   ./target/release/exav --help
   ```

3. Put the binary somewhere on your `PATH`:

   ```sh
   sudo install -m755 target/release/exav /usr/local/bin/exav
   ```

</Steps>

The default build handles every supported archive format and is already a
pure-Rust binary with no TLS stack. To add [HTTP(S) support](/reference/feature-flags/#adding-http-support)
(URL scanning and signature auto-update):

```sh
cargo build --release -p exav --features http
```

For an even smaller binary with fewer capabilities:

```sh
cargo build --release -p exav --no-default-features --features all-formats,decrypt
```

See [Feature flags](/reference/feature-flags/) for the full list of build-time
options.

## Container

The published image is a wire-level replacement for the ClamAV Docker image: the
same clamd port 3310 and protocol.

```sh
docker run -d -p 3310:3310 -v exav-db:/var/lib/exav ghcr.io/sylvinus/exav
```

See the [Docker guide](/guides/docker/) for signature population, environment
variables, and the dual-container updater pattern.

## WASM sandbox module

To run the scanner sandboxed (for untrusted signatures), build the
`wasm32-wasip1` module:

```sh
rustup target add wasm32-wasip1
cargo build --release --target wasm32-wasip1 -p exav-core --features wasi-bin
```

The output is `target/wasm32-wasip1/release/exav-wasm.wasm`. See the
[WASM sandbox guide](/guides/wasm-sandbox/) for how to run it under wasmtime.
